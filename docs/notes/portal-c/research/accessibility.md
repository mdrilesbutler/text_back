# Candidate C — WCAG 2.2 AA bar for the /client portal at 390 px (2026-10-26)

Scope: server-rendered FastAPI + Jinja2, one CSS file, one small vanilla JS module, must work with JS off.
Owner on a 390×844 phone (iPhone 14 class). Pages and states from
`docs/notes/ui-bakeoff-2026-10-26/design-prompt-100.md` (Home, Messages, Schedule, Calendar, Phone, Account,
Sign in): bottom nav, sticky jump chips, sticky Save bar, toasts, insert chips, quick-pick chips, carrier codes
under `<details>`, forwarding checklist, six-cell code entry, calendar connected/not-connected/test states.
Reference implementation read for context: candidate A `src/text_back/static/portal.css` (focus, forced-colors,
reduced-motion blocks) and `docs/notes/ui-compare-a/design-spec.md` §1.3 contrast table.

Conformance target: WCAG 2.2 Level AA. Three AAA criteria (2.4.12, 2.4.13, 2.3.3) are adopted anyway because
they cost one CSS rule each. Citations: https://www.w3.org/WAI/WCAG22/Understanding/<slug>.html.

## Toast rule (consolidated)

In-flow, not fixed. Rendered into the `#status` slot that sits between the sticky header and the `<h1>`, so it is
under the header and never over the title or intro. Server renders it after the save redirect (JS off); JS renders the
same markup into the same slot. Text names the change. Dismiss button 44 px. No auto-removal; it persists as inline
status until dismissed or the next navigation. Never receives focus; never `role="alert"`.

## Summary (10 lines)

1. The brief's #e7e5e4 border is 1.2:1 — decorative only; every control boundary must use #78716c (4.59:1) or darker.
2. The five brand colours otherwise clear AA with room: ink 17:1, muted 7.3:1, accent 6.8:1, white-on-accent 7.1:1.
3. 44×44 is C's rule for all tappable controls, including chips and `<summary>` rows; WCAG's 24 px is the floor axe checks.
4. One ring (2 px solid #166534, 2 px offset) everywhere; scroll-padding top AND bottom sized to the sticky chrome,
   updated when the Save bar appears, is the single thing that keeps 2.4.11 true.
5. Toasts live in an in-flow `role="status"` slot under the header, never fixed, never over the h1, never focused, never auto-removed.
6. Announce saves and segment-count changes only; never per-keystroke counts, chip toggles or preview re-renders.
7. Native semantics carry the states: radios for quick-picks, `role="switch"` checkboxes, one 6-char input (not six), `<details>` for carrier codes, `<ol>` for the checklist.
8. Errors are server-rendered: inline + linked summary that receives focus, each with a concrete fix; works with JS off.
9. One check vocabulary (Done / Not yet / You checked this) with word plus glyph; the brief's Home and Phone vocabularies must be mapped before mockups.
10. Runtime verification still needed: iOS VoiceOver on the real phone (focus ring with the on-screen keyboard open, OTP autofill), Windows High Contrast in Edge, real 200 % zoom; dark-theme ratios are unknown until C's tokens exist.
