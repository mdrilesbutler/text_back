# d1 — Spine
Idea: every page is one vertical story read top to bottom. A thin spine runs down the left with one node per thing that matters: setup items on Home, the conversation's steps on Messages, rules on Schedule, numbers, forwarding and the five checks on Phone, the connection on Calendar.
Two node kinds, never both on one fact: state nodes draw the status (filled tick = Done, amber ring with ! = Needs you, clock = Waiting, plain ring = Not yet, dashed ring with tick = You checked this) and the word sits beside them in a pill with no second glyph. Icon nodes (1px decorative ring) only label a section; a short tick on the line marks a sub-heading.
Borrowed from A: portal.css and its anatomy: message card (head, bubble, receipt line, Edit wording / Reset foot), amber cost warning, the one-input code entry, switch rows, pill radios, choice cards, the phone frame and thread.
New in rounds 1–2: a white page; real forms with one Save per form; a Save bar that sits above the bottom nav only while something changed, naming what changed; plain textareas with [Business name] inserts; the customer reply that triggers each fallback shown above it; "What happens next" on the steps-back cards; "Was:" under unsaved drafts.
Honesty: bubbles show only the customer's text and one line explains the network notice, which the counts include; preview data (This week, forwarding checks 1, 2 and 4, setup cards) carries Example tags; Home and Calendar say the same thing about the test calendar; build.py asserts the example and the confirmation match the switched-on questions.
Also: an error summary on the multi-field Phone form and inline errors on one-field forms, inline confirm (no modal) for Sign out everywhere, Account in the desktop sidebar, a desktop rail that stays below the header and scrolls its own thread, and d1.js (27 lines, optional) that marks the jump chip for the step on screen.
Signature element: the spine with its red missed-call dot on the Messages "Missed call" node, the same mark that opens the example thread, so the settings page and the customer's phone read as the same story.
Chrome budget on a phone: header 56 + jump chips 44 (Messages; hidden while unsaved) + nav 56, or header 56 + Save bar 56 + nav 56 = 168; html scroll-padding follows.
